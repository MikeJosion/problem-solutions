## 每个结构的统一完成标准

### 1. 接口完整

按结构特点实现下列操作；不适用的操作可以省略，但要在 README 解释：

- 初始化、清空、销毁；
- 判空、长度；
- 插入、删除、修改；
- 按位查找、按值查找；
- 遍历或打印；
- 容量受限结构的判满与扩容策略。

### 2. 边界安全

- 检查空指针和 `malloc/realloc` 结果；
- 不使用一个合法数据值（如 `-1`）同时表示操作失败，推荐通过 `bool + 输出参数` 返回；
- 删除动态结点后释放内存，整体结束时提供销毁函数；
- 明确索引从 `0` 还是 `1` 开始；
- 测试空、单元素、首部、尾部、中间、越界和重复元素。

### 3. 408 表达

每个目录建议包含一个简短 README，至少回答：

- 逻辑结构和物理结构是什么；
- 每个核心操作的时间、空间复杂度；
- 常见易错点；
- 与同类结构相比适合什么场景。

### 4. 工程结构

完整实现推荐拆分为：

```text
结构名称/
├── README.md       # 原理、复杂度、易错点、掌握状态
├── structure.h     # 类型和公开接口
├── structure.c     # 接口实现
├── main.c          # 边界测试
└── CMakeLists.txt
```

当前部分早期代码仍把接口、实现和测试写在一个 `.c` 中，可以边复习边逐个迁移，不需要一次全部重写。

## 推荐优先级

1. 先补全线性表、栈、队列的接口和边界测试；
2. 再统一树和图的创建、遍历、销毁接口；
3. 补齐串、查找、排序；
4. 最后做综合题并链接到 `408题库/数据结构`。
